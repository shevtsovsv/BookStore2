# Обработчик оформления заказа: контроль одновременных операций

## Как работает checkoutController.js

### 1. Получение корзины пользователя

- При вызове `/api/cart/checkout` (POST) контроллер сначала получает все товары из корзины текущего пользователя.
- Загружается информация о книгах, включая текущий остаток (`stock`) и количество продаж (`popularity`).

### 2. Атомарность через транзакцию

- Весь процесс оформления заказа выполняется внутри одной транзакции Sequelize (`sequelize.transaction`).
- Если на любом этапе возникает ошибка (например, недостаточно товара), вся операция откатывается, и данные в БД не меняются.

### 3. Row-level locking (блокировка строк)

- Для каждой книги, которую покупает пользователь, происходит выборка с блокировкой строки: `Book.findByPk(bookId, { lock: t.LOCK.UPDATE, transaction: t })`.
- Это гарантирует, что параллельные покупки одной и той же книги не приведут к перепродаже: пока одна транзакция не завершится, другая ждёт освобождения блокировки.

### 4. Проверка остатка

- После блокировки строки книги проверяется, достаточно ли товара (`book.stock < quantity`).
- Если товара недостаточно, выбрасывается ошибка с точным указанием доступного и запрошенного количества, транзакция откатывается, пользователь получает сообщение.

### 5. Обновление данных

- Если товара достаточно, происходит:
  - Уменьшение остатка: `book.stock -= quantity`
  - Увеличение счётчика продаж: `book.popularity = (book.popularity || 0) + quantity`
- Изменения сохраняются только внутри транзакции.

### 6. Очистка корзины

- После успешной покупки всех товаров корзина пользователя автоматически очищается (`CartItem.destroy`).

### 7. Гарантия целостности

- Если два пользователя одновременно покупают одну и ту же книгу:
  - Первый получает блокировку строки, завершает покупку, обновляет остаток.
  - Второй ждёт, получает уже обновлённые данные, и если товара недостаточно — получает ошибку.
- Это полностью исключает race condition и перепродажу.

## Отображение в статистике

### Общее количество проданных книг

- Вычисляется как сумма всех значений поля `popularity` из таблицы `books`:
  ```javascript
  const totalSold = await Book.sum("popularity");
  ```

### Количество проданных книг по категориям

- Для каждой категории вычисляется сумма `popularity` всех книг этой категории:
  ```javascript
  const genresWithSales = await Category.findAll({
    attributes: [
      "id",
      "name",
      [
        Book.sequelize.fn("SUM", Book.sequelize.col("books.popularity")),
        "totalSold",
      ],
    ],
    include: [{ model: Book, as: "books", attributes: [], required: true }],
    group: ["Category.id", "Category.name"],
    order: [
      [
        Book.sequelize.fn("SUM", Book.sequelize.col("books.popularity")),
        "DESC",
      ],
    ],
  });
  ```

### Обновление статистики в реальном времени

- После успешного оформления заказа значения `popularity` для всех купленных книг увеличиваются.
- При следующем запросе к `/api/books/stats` статистика автоматически пересчитывается и показывает актуальные данные.
- Изменения видны на главной странице в блоке статистики.

## Как выполняются требования к одновременным операциям

✅ **Транзакции ACID** — все операции атомарны, либо проходят полностью, либо откатываются.

✅ **Row-level locking** — блокировка записи книги на время покупки (`lock: t.LOCK.UPDATE`).

✅ **Проверка остатка** — всегда актуальные данные, даже при высокой нагрузке.

✅ **CHECK constraint** — можно добавить на уровне БД для дополнительной гарантии (`stock >= 0`).

✅ **Валидация на уровне приложения** — реализована в контроллере с подробными сообщениями об ошибках.

✅ **Race condition handling** — исключён благодаря транзакциям и блокировкам.

✅ **Атомарное обновление статистики** — поле `popularity` обновляется в той же транзакции, что и `stock`.

## Пример работы

### Сценарий 1: Успешная покупка

1. Пользователь нажимает "Оформить заказ" на странице корзины
2. Frontend отправляет POST запрос на `/api/cart/checkout`
3. Backend получает корзину пользователя (например, 2 книги: ID=1 qty=3, ID=5 qty=1)
4. Начинается транзакция
5. Для книги ID=1: блокировка → проверка stock (достаточно) → stock -= 3, popularity += 3 → сохранение
6. Для книги ID=5: блокировка → проверка stock (достаточно) → stock -= 1, popularity += 1 → сохранение
7. Очистка корзины пользователя
8. Commit транзакции
9. Ответ: `{ success: true, message: "Заказ успешно оформлен!" }`
10. Статистика на главной странице автоматически обновится при следующем запросе

### Сценарий 2: Недостаточно товара

1. Пользователь пытается купить 10 экземпляров книги, но на складе только 3
2. Backend начинает транзакцию
3. Блокирует строку книги
4. Проверяет остаток: `stock (3) < quantity (10)` — условие не выполнено
5. Выбрасывается ошибка: `"Недостаточно товара: [название книги]. Доступно: 3, запрошено: 10"`
6. Транзакция откатывается — никакие данные не изменились
7. Ответ: `{ success: false, message: "Недостаточно товара..." }`
8. Корзина остаётся без изменений

### Сценарий 3: Одновременная покупка двумя пользователями

1. Пользователь А и Пользователь Б одновременно пытаются купить последние 5 экземпляров одной книги
2. Пользователь А: запрашивает 3 шт.
3. Пользователь Б: запрашивает 3 шт.
4. Транзакция А начинается первой → блокирует строку → stock = 5, достаточно → покупает 3 шт. → stock = 2, popularity += 3 → commit
5. Транзакция Б ждёт освобождения блокировки → получает обновлённые данные → stock = 2 < 3 → ошибка
6. Результат: Пользователь А успешно купил 3 книги, Пользователь Б получил ошибку "Недостаточно товара: доступно 2, запрошено 3"

## Итог

Обработчик `checkoutController.js` полностью соответствует требованиям к одновременным операциям и гарантирует:

- Корректный учёт продаж даже при высокой нагрузке и параллельных покупках
- Отсутствие перепродажи товара
- Актуальную статистику продаж в реальном времени
- Целостность данных при любых сценариях использования
